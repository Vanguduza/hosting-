# Isolated committed audit-event receiver

`services/event_receiver.py` is a separately deployable sink for the control outbox. It binds to `127.0.0.1:9152` and accepts `POST /ingest` only behind an independently managed HTTPS reverse proxy. It verifies the sender's HMAC-SHA256 against the raw body, the fresh request timestamp, exact ID header and canonical audit fields. It recomputes each event hash, checks that its predecessor matches the most recently persisted event for that organization, and commits the event and organization head in one synchronous SQLite transaction before returning 202. The sender retries on a non-2xx response. A byte-identical retry receives 202, including a replay after later events; a changed ID, broken chain, or out-of-order first delivery is rejected. The original outbox sends old audit facts in tenant order when first enabled, so initialize this receiver before starting event delivery.

Create root-owned mode-0600 `/etc/dial-event-receiver/signing-key` with the same 32–4096 raw bytes used by `EVENT_SINK_SECRET_FILE` on the sender. Create `/etc/dial-event-receiver/receiver.env` from the example, set the expected event floor, then run `sh deploy/event-receiver/install.sh` on a separate supervised host. Point the sender's fixed `EVENT_SINK_URL` at the proxy's HTTPS `/ingest` route. The proxy must pass the exact body and `X-Dial-Event-*` headers unmodified, restrict this route to the sender where possible, and apply a small body and connection limit. The loopback port is never a public endpoint. `GET /live` proves only that this process is alive. The health timer walks all persisted events and independently recomputes every tenant chain and head; it also fails if the configured minimum event count is absent. Supervise the host and failed timer from another failure domain.

The event receiver keeps audit facts, including actor subjects and resource IDs; protect its database and do not use it as a public tenant API. It is an operator sink, not a tenant notification service or a complete fan-out event fabric. An offsite copy is required: initialize a separate encrypted Restic repository, create root-owned mode-0600 `/etc/dial-event-receiver/backup.json`, `restic-password`, and `restic.env` from the examples, then run `sh deploy/event-receiver/install-backup.sh`. The daily online SQLite backup is restored into a disposable directory and the tenant chains and head rows are checked against the snapshot digest before issuing a verified receipt. The hourly check confirms the latest verified snapshot still exists in Restic. To drill on a recovery host after the source database is unavailable, bring the protected receipt directory and Restic access, then run `python3 tools/alert_receiver_backup.py restore --config /etc/dial-event-receiver/backup.json --snapshot-id FULL_ID`. Preserve the signing key separately; the SQLite backup does not include it.

The CI sender-to-receiver test covers HMAC delivery, missing predecessors, replay, and persisted chain tampering. The Restic test restores the receiver after the source file is removed. Host placement, TLS ingress, external supervision, retention capacity, and a cross-host recovery drill remain production qualification inputs.
