# Reserved capacity accounting

Migration `017_capacity_intervals.sql` records one durable reservation interval per application release, PostgreSQL instance, Valkey instance and Garage storage instance. The insert trigger runs in the same database transaction that reserves the node and creates the resource. A release interval closes only when the worker has confirmed retirement or failed-release cleanup and released the node reservation. A failed resource whose reservation remains allocated stays open. The managed data resource APIs do not yet support deletion, so their intervals remain open. The API and worker cannot directly insert, update or delete ledger entries.

An existing installation starts coverage at the migration timestamp. Active rows are backfilled from that epoch; historical time before it is **not** reconstructed or charged. `GET /v1/organizations/{organization_id}/capacity?from=YYYY-MM-DDTHH:MM:SSZ&to=YYYY-MM-DDTHH:MM:SSZ` accepts UTC timestamps in that exact order, a positive interval of at most 31 days, and clips a future end to the current instant. An interval starting before the migration epoch gets `409 capacity_coverage_unavailable`. Owners, admins and viewers can read only their own organization's totals; machine service tokens cannot use the route. `tools/hosting_cli.py capacity <org UUID> <from UTC> <to UTC>` calls the same route.

Each resource type reports the count of overlapping reservations, `reserved_cpu_milli_ms` and `reserved_memory_mb_ms`. The units are **allocated milliCPU × milliseconds** and **allocated MiB × milliseconds**. Counts across types are not unique applications. Node reservations are placement capacity, not a measured CPU/RAM consumption signal. No price, tax, invoice, quota decision or payment action is derived from this ledger. Billing still requires measured usage where appropriate, entitlement rules, immutable financial period closure, an invoice/payment provider, reconciliation, refund handling and end-to-end financial proof.

The control database physical/logical backup covers the ledger and its coverage epoch. A restored ledger must be checked against node resource ownership and release cleanup receipts before an operator bills from it. A privileged database administrator could alter ledger rows; the platform roles have no ledger write grant. Keep protected database backup and audit evidence outside the serving host's failure domain.
