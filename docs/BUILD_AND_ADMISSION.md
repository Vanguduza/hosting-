# Trusted application build and admission

The build node is distinct from every production runtime node. It runs a rootless Docker Engine and a named Buildx `docker-container` builder. Registry credentials and a dedicated Cosign signing key live on the builder only; the runtime agent receives neither. Only DIAL-controlled source is admitted in this profile. Arbitrary external client or untrusted PR code requires a certified stronger isolation class.

`tools/build_release.py` requires a clean checked-out full Git commit, a Dockerfile within that checkout, a registry repository, a named isolated builder, the signing key, the corresponding public key, an operator admission database connection, policy revision, and an owner-only evidence directory. It pushes a temporary SHA-tagged image, reads the immutable digest from Buildx metadata, signs that digest, verifies the signature, runs Trivy vulnerability/secret checks, produces a CycloneDX SBOM with Syft, and writes an admission receipt to the control DB. Only the digest is accepted by the release API. A failing signature, scanner, SBOM or database insertion prevents admission.

Before running it, qualify and pin the Docker/Buildx, BuildKit, Cosign, Trivy and Syft versions and verify the isolated node's registry, CPU, memory, network and disk budgets. The current repository does not automate GitHub webhooks, PR previews, client code isolation, key rotation, license approval or Harbor provisioning. These remain separate gates; a digest in the admission table alone is not a production release certificate.
