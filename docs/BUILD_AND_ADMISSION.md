# Trusted application build and admission

The build node is distinct from every production runtime node. It runs a rootless Docker Engine and a named Buildx `docker-container` builder. Registry credentials and a dedicated Cosign signing key live on the builder only; the runtime agent receives neither. Only DIAL-controlled source is admitted in this profile. Arbitrary external client or untrusted PR code requires a certified stronger isolation class.

`tools/build_release.py` requires a clean checked-out full Git commit, a Dockerfile within that checkout, a registry repository, a named isolated builder, the signing key, the corresponding public key, a **restricted** `HOSTING_ADMISSION_DSN` for role `hosting_admitter`, policy revision, and an owner-only evidence directory. The role can only read and insert artifact admission evidence; it cannot read tenant data, update releases or own schema. The script rejects migration/admin credentials before scanning. It pushes a temporary SHA-tagged image, reads the immutable digest from Buildx metadata, signs that digest, verifies the signature, runs Trivy vulnerability/secret checks, produces a CycloneDX SBOM with Syft, and writes an admission receipt to the control DB. Only the digest is accepted by the release API. A failing signature, scanner, SBOM or database insertion prevents admission.

Create the `hosting_admitter` role through the protected `00_create_api_role.sh` bootstrap and apply migration `008_admission.sql`. On existing control databases, create the role with an independently generated password and apply that migration before switching the builder's connection. Keep its credential on the isolated build host, never on a runtime node. Before running it, qualify and pin the Docker/Buildx, BuildKit, Cosign, Trivy and Syft versions and verify the isolated node's registry, CPU, memory, network and disk budgets. The current repository does not automate GitHub webhooks, PR previews, client code isolation, key rotation, license approval or Harbor provisioning. These remain separate gates; a digest in the admission table alone is not a production release certificate.

Admission evidence files are atomically linked into an owner-only directory before the database row is committed. A repeat of the same digest, commit, policy and key returns the recorded receipt only after checking the local signature, scan and SBOM evidence against their hashes and the database row. A crash after all files were saved but before the DB commit can replay that exact evidence. Missing or changed files fail closed and need operator reconciliation; never delete or rewrite evidence to force a replay.
