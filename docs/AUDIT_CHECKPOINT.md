# Off-host audit checkpoints

`tools/audit_checkpoint.py` reads every organization's committed audit events in a consistent PostgreSQL snapshot. It checks each per-tenant hash chain, then records the organization ID, event count, final event ID/hash and a SHA256 digest of every row including its timestamp. It HMAC-signs the document with an owner-protected key and publishes it to a separate encrypted Restic repository with `dial-audit-anchor` and anchor ID tags. A zero-event organization is included. The publisher requires a protected full-tenant database reader with BYPASSRLS or superuser, never the API or worker role.

Create a root-owned mode-0600 JSON config with exactly `version` (1), `anchor_id`, `source_failure_domain`, `recovery_failure_domain`, `repository`, `password_file` and `signing_key_file`. The two named failure domains must differ. The repository must be an explicitly remote Restic URL and initialized with its independent password file. Protect the signing key file and password file with the same owner-only checks; use at least 32 random bytes in the signing key. Supply the protected database connection through `DB_HOST`, `DB_NAME`, `DB_USER` and `DB_PASSWORD_FILE`.

Run `python tools/audit_checkpoint.py --config /etc/dial-hosting/audit-checkpoint.json publish` from a protected operator environment, and record the full snapshot ID outside the source host. Schedule publication and alert if an expected snapshot is absent or stale. On an independent recovery host with the Restic password, signing key, config and restored database, run `python tools/audit_checkpoint.py --config /etc/dial-hosting/audit-checkpoint.json inspect <full-snapshot-id>`. It restores the selected encrypted snapshot into a temporary directory, verifies the remote tags and HMAC, then compares each anchored chain prefix against the database. Events legitimately appended after the checkpoint are allowed. A missing organization, changed timestamp, missing event or modified hash chain fails inspection.

This checkpoint is an external comparison point, not proof of immutable storage. Anyone who can replace the off-host repository and obtain the signing key can forge a new checkpoint. Production qualification requires separately governed key custody, retention or object lock, restore drills on the selected estate, and an alert on publication or inspection failure. The database's own readback endpoint remains described in [tenant audit readback](AUDIT_READBACK.md).
