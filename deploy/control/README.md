# Control plane local profile

This profile is a **private development environment** for the implemented organization/project API; it is not a production PaaS deployment. It does not start any named dependency from the full blueprint until its exact version and placement are admitted.

1. Install a Docker Engine and Compose plugin on an isolated developer host.
2. Copy `.env.example` to `.env` and set a real OIDC issuer, audience and JWKS URL; obtain a JWT for that audience. Create `.secrets/pg_admin`, `.secrets/pg_api`, `.secrets/pg_worker`, `.secrets/pg_admitter`, `.secrets/pg_hook`, and `.secrets/pg_buildworker` with independent random passwords (at least 32 characters) and mode 0600. Create `.secrets/github_webhook` with an independent random secret of at least 32 bytes and mode 0600. Compose file secrets are local files, not a production secret store.
3. Run `docker compose --env-file .env up --build`. A fresh database creates restricted API, worker, admission, hook and buildworker roles. The short-lived `migrate` service applies ordered SQL migrations in one transaction, writes immutable SHA-256 history, and must complete before API, hook or worker startup. Each serving process also checks the complete migration history against its own image at startup, including after a previously successful migrator container. For upgrades, run `docker compose --env-file .env run --rm migrate` **before** replacing any serving process. Changed or missing applied SQL is rejected. A legacy database created by an earlier version without a migration ledger is deliberately rejected: back it up, audit its installed schema and migration history, then perform an explicit reviewed adoption or recreate only a disposable development volume. Never mark uncertain production migrations applied. The signed hook listens on loopback port 8081; publish it through a TLS ingress if enabling GitHub push builds. See [trusted source builds](../../docs/BUILD_AND_ADMISSION.md).
4. To create the first organization, run `tools/bootstrap_org.py` against a private database-admin connection (`HOSTING_MIGRATION_DSN`) and pass an independently verified `sub` from the issuer. The command refuses the serving role. Protect and audit this operator credential; enrollment is separate from ordinary API permissions.
5. Keep the API loopback-only. Add a TLS/identity-aware ingress and rate limiting before any remote access.

An organization owner can add an existing OIDC user through the [one-time team invitation flow](../../docs/TEAM_MEMBERSHIP.md). This does not grant owner transfer or identity-provider administration.

## Deployment worker

The separate `worker.compose.yaml` only starts after a private runtime node and its node agent have been enrolled. Place the node CA certificate and distinct client certificate/key in `.secrets/node_ca.pem`, `.secrets/node_client.pem`, `.secrets/node_client.key`. The node agent requires the client CN and its own server key/cert. Configure a TLS OpenBao origin in `BAO_ADDR`, and provide `bao_ca.pem`, `bao_role_id`, `bao_secret_id` files in `.secrets`; see [secret setup](../../docs/SECRETS.md). Enroll via `tools/register_node.py` on a private operator connection; it obtains live capacity over mTLS. Admit an immutable signed image with `tools/admit_image.py`, which executes Cosign, Trivy and Syft before writing its evidence receipt. Apply all numbered SQL migrations with the dedicated migration role before starting a worker against an existing database. Then run:

```bash
docker compose -f deploy/control/compose.yaml -f deploy/control/worker.compose.yaml \
  --env-file deploy/control/.env up --build
```

The resource API also accepts `POST /v1/organizations/{org}/applications/{app}/postgres` with a UUID `idempotency_key`, `memory_mb` (256–32768), and `cpu_milli` (100–32000). Read its state with `GET` on the same path. Its worker provisions one private PostgreSQL instance bound to that application and pins future releases to its node. Configure `NODE_POSTGRES_IMAGE` with a tested PostgreSQL 17 tag plus immutable digest on the node. Application containers receive `DATABASE_HOST`, `DATABASE_NAME`, `DATABASE_USER`, and `DATABASE_PASSWORD_FILE` and join only their own database network. A ready instance is not a backup or production certification: [managed PostgreSQL operations](../../docs/MANAGED_POSTGRES.md) lists recovery and missing production controls. Do not expose this profile to clients. Image admission and node enrollment must use audited protected operator credentials and private networking.

The `/live` probe means only that the process exists; `/ready` requires a valid JWT and successful database query. Neither asserts deployment or hosting health. Do not point a public hostname at this API until authenticated rate limits, TLS and production readiness have been verified.
