# Node agent security and operation

This is a Linux-only, private-network process. Run one instance per dedicated runtime node under a service account with Docker Engine access. That access is host-equivalent privilege: keep it isolated from the control API, customers and public interfaces. The agent accepts typed operations for digest-pinned deployments, resource provisioning, route management and observed state. The private `PUT /v1/application-state` action pauses or resumes only the labeled active release when no public route exists; resume requires a fresh private health probe. No shell endpoint, arbitrary Compose input or forwarded Docker socket exist.

Provision a private CA and unique short-lived server/client certificates with a renewal and revocation procedure. The server certificate must include its private IPv4 address as an IP SAN. Set `NODE_CLIENT_CN` to the control-worker certificate's CN. Configure `NODE_BIND` to a private interface, not a public interface. Require a firewall policy allowing only the control worker; configure `NODE_STATE_FILE` on a persistent disk; back it up and protect it. Rotation must preserve in-flight idempotency records.

`PUT /v1/deployments` requires a UUID operation ID, application ID, release ID, OCI image digest, internal HTTP port and path, and bounded CPU/RAM limits. A successful receipt says `HEALTHY_PRIVATE`; it **does not** claim a public route, TLS, backup, supply-chain admission or production eligibility. A prior healthy container remains present until replacement passes the private HTTP probe. The same request can be replayed after a controller restart without changing identity.

The control plane must check actor, tenant, policy, artifact signature, placement and quota before calling the agent. This process does not make those platform decisions. A failed deploy retains the previous active container; it is not a public-traffic rollback controller. Application containers receive only the exact revision of approved private database/cache/object-storage credentials when such resources are attached. They run read-only as UID 10001 with dropped capabilities, a PID limit, CPU and memory limits. The image must support that runtime contract.

`deploy/node-agent/install.sh` installs the Python package and systemd service after the operator supplies an owner-only environment file and mTLS certificates. Make the private key readable to the `dial-node` group only (`root:dial-node`, mode 0640); keep the environment file root-only (0600). The installer does not pick a node or expose one publicly. Docker group membership is effectively host privilege; only the restricted agent process receives it. A private firewall must permit the chosen worker IP and deny other clients.
